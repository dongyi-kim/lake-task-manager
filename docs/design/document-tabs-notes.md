# Confluence 최근 문서 탭

`ConfluenceView`는 공용 `createOpenItemTabs`와 `OpenItemTabs`를 사용한다. Task 탭과 별도로 환경·Jira 주소·프로젝트·Confluence 주소가 모두 확정된 범위에서 ID, 제목, 스크롤, 활성 탭만 복구한다. 본문·초안·첨부·발행 기록은 탭 저장소에 넣지 않는다.

- 초기 진입은 직접 지정한 문서 ID를 우선하며, 없으면 저장된 활성 문서 한 건만 기존 `readConfluence`로 읽는다. 비활성 탭 복구와 닫기는 본문을 조회하지 않는다.
- 문서 링크, 직접 hash 변경, 뒤로가기, 탭 활성화는 같은 전환 경로를 사용한다. 편집 중에는 `Composer.close({requireDurable:true})`가 본문 초안과 폼 저장을 완료한 경우에만 선택·탭·URL을 바꾼다. 복원 중, 발행 중, 저장 실패에는 전환하지 않는다.
- 현재 문서 탭을 다시 누르면 편집 상태를 유지한다. 전환 실패로 탭의 disabled 상태가 풀린 뒤에는 기존 키보드 초점을 복구하며 사용자가 다른 입력으로 옮긴 초점은 빼앗지 않는다.
- 닫기는 각 저장 await 전후에 편집기의 발행·AI·초안 충돌 상태와 동일 인스턴스를 확인한다. 편집 tick이나 폼·발행 기록 snapshot이 저장 도중 바뀌면 화면을 유지하고 다시 이동하도록 안내한다. 발행은 에디터의 초기 Jira-context 대기부터 발행 완료 초안 정리까지 닫기를 차단한다.
- Composer의 기존 `run`과 mutation ID는 그대로 저장한다. 결과가 불확실한 발행을 탭 닫기로 폐기하거나 새 발행으로 바꾸지 않는다. 전체 화면 이동은 기존 keep-alive가 편집기를 보존한다. 비활성 화면은 hash 변경으로 문서를 조회하지 않으며 진행 중인 닫기 요청도 편집기를 숨기지 않는다.
- 활성 탭을 닫으면 오른쪽, 없으면 왼쪽 이웃 한 건을 읽는다. 마지막 탭은 빈 문서 탐색 화면으로 돌아가고 트리 검색으로 초점을 옮긴다. 스크롤은 전환 전 즉시 저장하고 본문 렌더 후 복구한다.
- 탐색 세대와 기존 읽기 세대로 늦은 전환·본문 응답을 차단한다. 문서 본문/목차/편집기/트리의 기존 3열 구조와 resize 동작은 유지하며 바깥 `.conf-view`만 탭 줄과 workspace를 세로로 배치한다.

수정 파일: `ConfluenceView.js`, `ConfluenceComposer.js`, `confluence.css`의 wrapper 규칙 한 개, `tests/frontend/shell/test_confluence_tab_guards.py`, 이 문서. API·백엔드·발행 요청 내용은 변경하지 않았다.

검증: Node 구문 검사 2개와 11개 메서드 계약 검증 통과(메타데이터만 보관, 스크롤 복구, 저장 실패 시 hash/선택/조회 차단, 비활성 닫기 무조회, 이웃 한 건 조회, 마지막 닫기 무조회, 겹친 전환, 늦은 응답, 불확실한 발행 기록 보존, busy/복원/저장 실패 차단, 화면 이탈 중 닫기 취소). `git diff --check` 통과. 실제 브라우저·통합 테스트는 root가 소유하며 이 기록은 DOM 접근성이나 전체 E2E 통과를 뜻하지 않는다.

후속 회귀 검증: 신규 순수 Node 계약 pytest 4개 통과. 실제 `submitWithAdapter`의 첫 flush 대기 중 닫기, publish 준비 구간, 두 저장 경계의 16개 상태 변경 조합, 동일 문서 편집 유지, 전환 실패 후 초점 복구를 포함한다. 테스트 실행 산출물은 OS 임시 폴더에서 정리했다.
