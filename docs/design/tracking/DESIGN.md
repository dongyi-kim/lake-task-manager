# Tracking — 첨부 대시보드 디자인 적용

## 기준

사용자 첨부 `jira-progress-dashboard-3.html`의 최종 CSS와 실제 렌더링을 시각 기준으로 사용.
이전 화면의 배치·색상보다 첨부 시안 우선. 기존 조회·집계·댓글·AI·복사 기능 보존.
데스크톱 1440px / 1280px 검증. 다른 페이지의 디자인 토큰 변경 없음.

## 구조

- 앱 헤더의 Tracking 제목 사용. 페이지 내부의 중복 타이틀 바 제거.
- 조회 도구 모음: 양끝 날짜 포함·한국 시간, 기간 프리셋, 다중 모듈·사람 선택, 이전 조회·AI 요약·보고서 복사.
- 상태: 저장된 조회 기간, 실제 관측 시각, 잠정 여부, 취소·재개, 수집 비용.
- 트리: WBS → Epic/가상 분류 → Task → Subtask. 모듈은 조회 조건이며 계층·상위 경로에 표시하지 않음.
  연결되지 않은 업무는 가상 `WBS 미연결`, 사용자 VOC는 가상 `사용자 VOC` WBS 아래 표시. 기존 업무·근거 보존.
- 본문: 선택 경로·제목 → 조회된 직속 하위 → 기간 변화 5지표·작은 그래프 → 현재 상태 분포 → 직속 하위 목록.
- 비종단 근거: 우측 상세 패널. 종단: 본문 전체를 상세로 전환. 트리 유지.
- Epic·Task 요약 제목 바로 아래와 Epic·Task·Sub-task 상세 상단: 선택 기간의 가로 시간축 표시.
  별도 근거 패널을 열지 않아도 선택한 Epic·Task의 시간축 확인. 상세를 열면 본문의 중복 시간축 숨김.
  실제 시각 간격을 보존한 단일 통합 축에 자체 상태·댓글과 직속 하위 주요 변화를 함께 표시.
  Epic은 Task, Task는 Sub-task 대상. 하위 작업별 축은 명시적 펼치기 옵션이며 기본 접힘.
  전체 기간 띠에서 날짜를 선택해 시간 확대. 09–18시/24시간 전환 및 범위 밖 사건 수 안내.
  상태 16px·댓글 18px 표식, 넓은 클릭 영역. 한 줄 24px 안내에 업무명·변화만 표시.
  선명한 2px 중립 실선 시간축·12px 굵은 날짜 눈금. 폭이 좁으면 날짜 간격을 늘려 겹침 방지.
  밀집 사건은 종류·시간 구간으로 압축. 표식 최대 3행, 안내 위·아래 1행씩. 넓은 축 안내 최대 6개·좁은 축 2개.
  단일 사건은 실제 시간 x좌표 유지. 복수 사건 표식은 구간 중앙에 배치하고 시간 범위·건수·작업 수 명시.
  호버·키보드 포커스 시 표식·연결선·안내 함께 강조. 원본 근거에 정확한 날짜·시각·출처 표시.
  가까운 댓글과 밀집 사건 묶음에서 모든 원본 사건 접근. 여러 티켓이 포함되면 작업 수와 각 원본 업무명·번호·시각을 명시. Esc로 닫고 표식으로 포커스 복귀.
  하위 생성·완료·재오픈·댓글·상태/담당자/마감일/우선순위 변경 표시. 제목·번호와 근거 이동 제공.
  확장·접기·댓글 표시·시간 확대는 저장 결과만 사용하며 집계와 선택 기간은 유지.
  조회된 하위 작업의 Done 수/전체 수와 완료 비율 표시. SP 기반 WBS 진척률·과거 진척률과 별도.
  상태 미확인·부분 수집은 잠정 수만 표시하며 비율 확정 금지. 공유 계층의 같은 티켓은 한 번 집계.
  상태 변화 미확인·활동 없음·부분 수집 구분. 현재 상태를 과거 기간의 시작 상태로 추정하지 않음.
  시간축은 상태선이 아님. 현재 상태는 별도 표시하고 미확인 과거 상태 구간을 채우지 않음.
  다른 범위·티켓 선택 시 본문/상세 스크롤을 상단으로 초기화. 같은 티켓 갱신은 위치 보존.
- 목록 4열: 업무·담당 / 기간 변화 / 현재 상태 / 확인 사항·근거.
- 완료: 이번 기간 / 기간 이후 / 시점 미확인 / 기간 이전 참고. 기본 10건, 이전 완료 5건 미리보기.
- 계층→상태 / 상태→계층 그룹핑, 고정, 검색·강조, 날짜별 활동, 계층별 집계 유지.

## 데이터·기능 계약

- 탐색·필터·그룹핑·고정·크기 조절: 저장 결과만 사용, 추가 Jira 수집 없음.
- 날짜·기간 중 담당 및 활동 대상·다중 모듈 조회 보존.
- 현재 상태와 기간의 완료 사건은 별도 사실. `asOf`는 조회 상한이며 관측 시각이 아님.
- 관측 시각은 `issue.fetchedAt`. 미확인과 0을 구분. 근거 없는 진척률·잔여 작업 생성 금지.
- `currentCompletion`: 완전하고 일관된 전체 상태 이력으로 입증한 최신 완료 진입 시점.
  Resolved→Closed는 동일 구간, 재오픈 후 재완료는 새 구간. 추가 REST 없음.
- 과거 저장 결과에 선택적 메타데이터가 없어도 열림. 완료 시점 미확인으로 표시.
- 공유 티켓·VOC·소속 Epic 없음·미수집 근거·재오픈 이력 유지.
- 댓글: 저장된 원문에 맞춰 HTML·인코딩된 HTML·wiki·일반 텍스트를 정화 후 표시. 코드 예시의 엔티티 보존.
  현재 Jira 설정과 다른 과거 댓글도 표시. 3줄 이상이면 2줄 미리보기, 펼치기/접기.
- 날짜별 활동: 그룹핑 안함 / 티켓별 / 날짜 내 티켓. 기존 잡음 필터 유지.
- 링크 활동: 새로 들어온 멘션임이 관계 정보로 확인된 기록만 유지. 직접 추가한 링크·삭제·교체·방향 미확인 기록 제외.
- AI: 실제 설정에 따라 활성화. 전체 조회 범위 요약임을 명시. 근거 이동·토큰 정보 유지.
- 복사: 범위·필터·불완전 상태·출처를 검토 가능한 대화상자.
- 취소와 중단/부분 수집 재개 구분. 오류 시 저장 결과 보존.
- 사용자 표시 이름: Jira 서버·환경별 장기 캐시. 90일 재사용, 연결 실패 시 365일 이내 이름 표시.
  담당자·작성자·멘션의 ID 대체 표시는 로컬 캐시로 보완. 이미 수집한 이름의 관측 시각 보존.
  티켓·인증 캐시 수명은 변경하지 않음. 출처를 확인할 수 없는 과거 이름을 다른 서버로 옮기지 않음.

## 구현 경계와 검증

조회 제어 `tracking-view.js`, 헤더·대화상자 `tracking-reference-template.js`.
본문 `trackingBriefingModel.js` / `tracking-briefing.js`, 트리·상세 `tracking-reference-nav.js` / `tracking-reference-detail.js`.
Tracking 전용 reference / panels / briefing CSS. 공통 댓글·활동 렌더러 재사용.
완료 시점 `app/tracking/completion.py`: 분석 결과에 선택적 메타데이터만 추가.

검증: 모델·컨트롤러·완료 시점 단위 검증, 실제 Vue/CSS 브라우저 회귀,
1440/1280 화면, 많은 하위 업무, 표·목록 댓글, 종단/비종단 이동, 다크 테마.
적용 스킬: frontend-design, omd-apply, subagent-driven-development, test-driven-development.
