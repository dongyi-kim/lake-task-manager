# Tracking — 첨부 대시보드 디자인 적용

## 기준

사용자 첨부 `jira-progress-dashboard-3.html`의 최종 CSS와 실제 렌더링을 시각 기준으로 사용.
이전 화면의 배치·색상보다 첨부 시안 우선. 기존 조회·집계·댓글·AI·복사 기능 보존.
데스크톱 1440px / 1280px 검증. 다른 페이지의 디자인 토큰 변경 없음.

## 구조

- 헤더: Tracking, 이전 조회, AI 요약, 보고서 복사.
- 조회: 양끝 날짜 포함·한국 시간, 기간 프리셋, 다중 모듈·사람 선택.
- 상태: 저장된 조회 기간, 실제 관측 시각, 잠정 여부, 취소·재개, 수집 비용.
- 트리: 모듈 → WBS → Epic/가상 분류 → Task → Subtask. 단일 모듈은 상단 이름으로 표시.
- 본문: 선택 경로·제목 → 조회된 직속 하위 → 기간 변화 5지표·작은 그래프 → 현재 상태 분포 → 직속 하위 목록.
- 비종단 근거: 우측 상세 패널. 종단: 본문 전체를 상세로 전환. 트리 유지.
- 목록 4열: 업무·담당 / 기간 변화 / 현재 상태 / 확인 사항·근거.
- 완료: 이번 기간 / 기간 이후 / 시점 미확인 / 기간 이전 참고. 기본 10건, 이전 완료 5건 미리보기.
- 계층→상태 / 상태→계층 그룹핑, 고정, 검색·강조, 날짜별 활동, 계층별 집계 유지.

## 데이터·기능 계약

- 탐색·필터·그룹핑·고정·크기 조절: 저장 결과만 사용, 추가 Jira 수집 없음.
- 날짜·기간 중 담당 및 활동 대상·다중 모듈 조회 보존.
- 현재 상태와 기간의 완료 사건은 별도 사실. `asOf`는 조회 상한이며 관측 시각이 아님.
- 관측 시각은 `issue.fetchedAt`. 미확인과 0을 구분. 근거 없는 진척률·잔여 작업 생성 금지.
- `currentCompletion`: 완전하고 일관된 전체 상태 이력으로 입증한 최신 완료 진입 시점.
  Resolved→Closed는 동일 구간, 재오픈 후 재완료는 새 구간. 추가 REST 없음.
- 과거 저장 결과에 선택적 메타데이터가 없어도 열림. 완료 시점 미확인으로 표시.
- 공유 티켓·VOC·소속 Epic 없음·미수집 근거·재오픈 이력 유지.
- 댓글: 기존 정화된 HTML 렌더러. 3줄 이상이면 2줄 미리보기, 펼치기/접기.
- 날짜별 활동: 그룹핑 안함 / 티켓별 / 날짜 내 티켓. 기존 잡음 필터 유지.
- AI: 실제 설정에 따라 활성화. 전체 조회 범위 요약임을 명시. 근거 이동·토큰 정보 유지.
- 복사: 범위·필터·불완전 상태·출처를 검토 가능한 대화상자.
- 취소와 중단/부분 수집 재개 구분. 오류 시 저장 결과 보존.

## 구현 경계와 검증

조회 제어 `tracking-view.js`, 헤더·대화상자 `tracking-reference-template.js`.
본문 `trackingBriefingModel.js` / `tracking-briefing.js`, 트리·상세 `tracking-reference-nav.js` / `tracking-reference-detail.js`.
Tracking 전용 reference / panels / briefing CSS. 공통 댓글·활동 렌더러 재사용.
완료 시점 `app/tracking/completion.py`: 분석 결과에 선택적 메타데이터만 추가.

검증: 모델·컨트롤러·완료 시점 단위 검증, 실제 Vue/CSS 브라우저 회귀,
1440/1280 화면, 많은 하위 업무, 표·목록 댓글, 종단/비종단 이동, 다크 테마.
적용 스킬: frontend-design, omd-apply, subagent-driven-development, test-driven-development.
