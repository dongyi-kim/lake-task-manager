# Tracking 진척 개요

## 화면 구성

기간 보고를 준비할 때 주요 업무의 결과와 현재 상태를 먼저 읽도록 구성한다.

- 상단: 이름이 있는 완료 업무, 하위 작업 진척, 재확인 업무를 최대 3개 제시. 해당 근거가 없는 종류는 생략.
- 목록: 업무·담당 / 기간 내 변화 / 수집 시점 현재 상태·남은 확인. 댓글과 하위 완료 상세는 행 펼치기 또는 근거 패널에서 확인.
- 보조 패널: 조회 전체의 완료 이력, 그중 현재 완료·미완료·미확인, 하위 완료, 생성, 댓글, 변경 집계. AI를 사용할 수 없으면 설정 안내를 접어서 표시.
- 근거 패널: 현재 상태, 기간 변화, 하위 완료 이력, 날짜별 원문 근거를 구분. 닫을 때 원래 업무 버튼으로 포커스 복귀.

기존 날짜·프리셋·모듈·사람·최근 실행·재개·취소, 검색·강조·고정·필터·복사, WBS 계층과 VOC 묶음, 날짜별 활동, 티켓 열기는 유지한다.

## 데이터 계약

`trackingOverviewModel.js`는 `buildTrackingReport`의 저장 결과만 읽는 순수 projection이다. 수집 API나 AI 요청을 실행하지 않는다.

- 기간 내 완료 사건과 수집 시점의 현재 상태를 분리한다. 현재 완료인 것만으로 기간 내 성과를 만들지 않는다.
- 완료 후 재오픈, 기간 밖에서 다시 바뀐 현재 상태, 상태 미확인을 구분한다.
- 하위 재오픈만 있는 기간에도 활동이 없다고 표시하지 않는다. 이후 현재 완료되었어도 기간의 재오픈 이력은 남긴다.
- 댓글은 날짜가 있는 최근 댓글 발췌로 표시한다. 댓글이나 일반 필드 변경만으로 업무 진척을 추론하지 않는다.
- 조회된 하위 집합은 전체 분모가 아니다. 전체 하위 완료율과 모듈 완료율을 계산하지 않는다.
- 부분 수집 합계는 잠정으로 표시한다. 재확인 건수에 증가만 가능한 값처럼 `+`를 붙이지 않는다.
- 검색·강조가 목록을 줄여도 집계는 조회 전체 범위임을 명시한다. 복사는 표시된 업무만 포함하고 현재 상태를 함께 적는다.
- 실제 payload에 없는 개발/운영 업무 분류와 Confluence 근거는 가상 시안에서 가져오지 않는다.

## 구조

- `trackingOverviewModel.js`: 행 요약, 현재 상태·재확인 분류, 주요 성과 선택과 집계.
- `tracking-overview.js`: 상단 주요 성과와 보조 집계 패널.
- `tracking-report.js`: 고정·표시 분류·압축 행·내용 펼치기·보고 복사.
- `tracking-view.js`: 기존 수집 controller, 보기 전환, 근거 연결과 포커스.
- `tracking-report.css`: 목록·펼친 내용·근거 패널.
- `tracking-overview.css`: 조회 상단·주요 성과·보조 패널. 앱의 기존 테마 토큰 사용.
