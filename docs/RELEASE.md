# RELEASE.json — 이 소스가 요구하는 실행기(런처) 세대

배포 정본은 **이 repo 의 릴리즈 태그**다. 유저의 `run.bat`(배포 repo 의 `bin/run-core.ps1`)이
GitHub 의 `releases/latest` 를 보고 그 태그의 소스를 받아 실행한다. **태그가 안 된 커밋은
유저에게 나가지 않는다** — dev 커밋은 자유롭게 쌓아도 된다.

## minLauncher

```json
{ "minLauncher": 1 }
```

런처는 자기 세대 번호(`run-core.ps1` 의 `$LauncherVersion`)를 갖고 있다. 받은 소스의
`minLauncher` 가 그보다 크면 **그 소스를 적용하지 않고**(기존 설치를 그대로 둔 채) 배포본
재설치를 안내하고 멈춘다.

이게 필요한 이유: 앱 소스는 자동으로 갱신되지만 **런처·config 는 배포 repo 에 있어서**
git 이 없는 유저에게 자동으로 가지 않는다. 그대로 두면 '옛 런처 + 새 소스' 조합이 생기고,
증상이 엉뚱한 곳에서 터진다. 릴리즈 노트에 적어 두는 방식은 **안 읽는 사람에겐 없는 것과
같다** — 그래서 도구가 막는다.

**언제 올리나** — 배포 repo 쪽(`run.bat` · `bin/` · `config/` 구조)이 바뀌어서, 새 앱 소스가
옛 런처로는 못 도는 배포에서만. 앱 코드만 바뀌는 평소 배포에서는 **건드리지 않는다**.
올리는 순간 전 유저가 수동 재설치를 해야 하므로, 정말 필요할 때만 올린다.

올릴 때는 배포 repo 의 `$LauncherVersion` 도 같은 값으로 올려서 함께 배포한다
(안 그러면 새 배포본을 받은 사람도 계속 안내 화면을 본다).
