# Tracking Density Correction Plan

**Goal:** Epic의 밀집 기록을 압축하고 날짜·시간축을 눈에 보이게 수정.

**Evidence:** 사용자 첨부 12905.jpg와 실제 DL-103 화면. 원본 31건, 표식 28개, 안내 16개, 높이 512px. 중심축은 1px 옅은 점선, 날짜 9px.

**Decision:** 시간축과 역사적 상태선의 의미를 분리. 시간축은 항상 선명한 중립 실선. 불명확한 과거 상태를 보간하지 않음. 밀집 사건의 개수와 시간 구간은 명시적 묶음으로 요약하며 모든 원본을 보존.

- [x] 순수 압축 모델: 의미별/시간 구간별 묶음, 출처별 원본, 정확한 시각 유지. 3행을 넘는 충돌은 명시적 혼합 묶음.
- [x] 배치 상한: 표식 3행, 안내 위·아래 1행씩, 넓은 축 최대 6개·좁은 축 2개. 그래프 192px.
- [x] 2px 실선·굵은 12px 날짜, 폭에 맞춘 날짜 생략 및 첫/마지막 눈금 보존. 실제 시간 좌표 유지.
- [x] 묶음과 전체 기록 목록: 각 원본의 업무명·번호·시각·변화·본문과 기존 근거 이동. Esc/포커스 복귀.
- [x] 모델·브라우저 회귀: 총수·원본 분할·VOC 범위·선택·추가 API 없음, 실제 DL-103과 좁은 상세 패널 검증.
- [x] 독립 검토·검증 결과 기록. 앱 브랜치에서 변경 보존하고 개발 revision을 대조하는 마무리 절차 수행.

## Contracts

- 직접 하위 범위·현재 완료 집계·불완전 수집 표시 유지.
- 단일 사건 좌표는 실제 시각. 집계 표식은 첫/마지막 사건의 중앙에 놓고 구간 선과 정확한 원본 시각 제공.
- 서로 다른 티켓의 댓글을 하나의 댓글로 취급하지 않음. 복수 출처 묶음은 작업 수와 각 원본 출처를 명시.
- 하위 작업별 축은 명시적 펼치기. 펼쳐도 각 축은 같은 밀도 상한 적용.
- 동일 checkout, 앱 저장소만 수정. 테스트·검토 임시 산출물은 OS 임시 디렉터리에서 정리.
