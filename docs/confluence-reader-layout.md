# Confluence 읽기 화면

## 디자인

LTM의 Pretendard와 기존 테마 토큰을 그대로 사용한다. 다크 기준 문서 배경
`#16181f`, 탐색 배경 `#1e212b`, 경계 `#282c38`, 본문 `#e4e6ec`, 보조 글자
`#b4b7c2`, 선택 강조 `#5b8def`다. 라이트는 동일 토큰의 기존 대응 색상을 따른다.
본문은 왼쪽 정렬하고 최대 78ch로 제한한다. 탐색·문서·목차를 별도 카드로 감싸지
않고 화면 하단까지 이어지는 세 영역으로 구분한다.

```text
넓은 창  [문서 탐색 ‹] ║ [도구 모음 / 문서 본문] ║ [목차 ›]
좁은 창  [문서 탐색]   [즐겨찾기 / 최신 확인 / 원문 / 목차]
                       문서 본문
```

- 양쪽 경계선을 드래그하거나 포커스 후 방향키로 폭을 조절한다. Home/End는 최소/최대다.
- 접힘 여부와 폭은 로컬에 저장한다. 조절 중 본문에 최소 480px를 남긴다.
- 1,100px 이하에서는 문서를 먼저 보여준다. 탐색과 목차는 native dialog로 하나씩 열리며
  Escape, 바깥 클릭, 항목 선택으로 닫힌다. 모바일 사용이 데스크톱 접힘 설정을 바꾸지 않는다.
- 네이티브 스크롤바는 숨기되 본문·트리·목차의 스크롤은 유지한다. 본문은 키보드로도 이동한다.
- 전체 창과 문서 본문에 중복 스크롤을 만들지 않는다. 좁은 창의 앱 탭은 가로로 탐색한다.

## 검증

`tests/frontend/shell/test_confluence_browser_ui.py`의 실제 브라우저 회귀 7개 통과:

- 기존 트리·즐겨찾기·검색·revision 확인·본문 교체·목차 이동과 scrollspy.
- 좌우 드래그, 키보드 폭 조절, 접기, 재로드 후 폭과 접힘 복원. 조절 자체의 본문 API 호출 없음.
- 700×844, 390×844에서 본문 높이가 viewport의 65% 초과, 페이지 가로/세로 overflow 없음.
- 좁은 창의 native modal, 배경 포커스 차단, Escape·바깥 클릭·항목 선택 닫기, 포커스 복귀.
- 본문 PageDown과 숨긴 스크롤바, 목차 이동 후 본문 heading 포커스.
- 패널에서 Ctrl/Cmd+K 또는 `/`로 통합검색을 열면 패널을 먼저 닫고 검색 입력으로 이동.
- 캐시 설정 저장·복원, 통합검색 연결, 인증 실패 시 본문 유지 및 권한 실패 시 제거.

Confluence 및 앱 루트의 자산 문법·템플릿 검사 13개 통과. 인위적 지연은 사용하지 않았다.
운영 Confluence의 공동 편집 검증 범위를 확대하는 변경은 아니다.

## 검토 결과

1. `app/static/components/ui/ConfluencePanel.js:16`의 native modal이 통합검색을
   가리던 P2 결함을 발견했다. 검색 단축키가 앱으로 전달되기 전에 panel을 닫도록 수정했고
   700/390px 브라우저 회귀에 검색 입력 포커스와 Escape 복원을 추가해 통과했다.
   입력창에서 일반 `/` 문자를 입력할 때는 패널을 닫지 않는다.

변경 크기·호환성·테스트·모델 컨텍스트 검토에서 다른 결함은 발견되지 않았다.
