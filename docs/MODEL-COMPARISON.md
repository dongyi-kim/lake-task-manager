# 모델 비교 — gpt-4o vs gpt-5 (2026-08-08)

에이전트의 **complex 역할**(Historian/Refiner/Assigner/Reviewer/Responder/PMO/Curator)만
대상 모델로 바꾸고, **simple 티어(Planner/Operator)와 채점 judge 는 양쪽 모두
gpt-4o-mini 로 고정**해 무거운 역할의 모델 차이만 비교했다.
측정 도구: `tools/agent_perf.py`(정량) · `tools/agent_scenarios.py`(정성, 4축 judge).
코드 기준: P-0~P-2 최적화 반영본(dca67b2).

## 정량 — 대표 4시나리오(조회/지식/생성/수정) 1회씩

| 모델 | 합계 시간 | LLM 호출 | 토큰 | 비용 |
|---|---|---|---|---|
| gpt-4o-mini (참고, 전 역할) | 155s | 33회 | 161k | $0.028 |
| **gpt-4o** | **215s** | 31회 | 150k | $0.41 |
| **gpt-5** | **1,108s** | 41회 | 300k | $1.05 |

- gpt-5 는 gpt-4o 대비 **5.2배 느리고 2배 토큰**(reasoning 토큰이 completion 으로 청구),
  2.5배 비용. 생성 플로우 한 턴이 574초 — 대화형 UX 로는 사실상 못 쓴다.
- gpt-5 는 호출 수 자체도 늘었다(31→41회): 생각이 깊어지며 도구 왕복이 많아진다
  (historian 3→7회, assigner 4→6회).
- gpt-4o 의 시간 병목은 호출당 지연(assigner 4회 37.6초)이지 토큰이 아니다.

## 정성 — 배터리 6케이스(에픽·벌크·지식·활동·수정·연관성), 동일 judge(mini)

| 케이스 | gpt-4o | gpt-5 | 비고 |
|---|---|---|---|
| EPIC1 에픽 생성 인터뷰 | ✓ 4.25 (189s) | ✓ 4.5 (**923s**) | gpt-5 품질 우위, 시간 5배 |
| BULK3 벌크 개별 배정 | ✗ 체커 실패 | ✓ 4.25 (**1,131s**) | gpt-5 만 승인 카드까지 완주 |
| KNOW4 사내+외부 지식 | ✗ | ✗ | 둘 다 체커 실패 — mini 는 통과. 아래 참고 |
| ACT5 티켓 유관자 활동 | ✓ **5.0** (31s) | ✓ 5.0 (137s) | 동점 — 사전 취합(코드)이 답의 뼈대라 모델 차이 없음 |
| MOD8 라벨·컴포넌트 수정 | ✗ | ✗ | 둘 다 "새 라벨 추가 확인" 질문으로 선회 — mini 는 즉시 카드 |
| REL14 연관성 규율 | ✓ 3.25 (75s) | ✓ 4.0 (274s) | 뜬금 티켓 인용은 양쪽 모두 0건 |
| **통과/평균** | **3/6 · 4.17** | **4/6 · 4.44** | |

### 해석

- **큰 모델은 신중해서 체커에 걸린다.** KNOW4·MOD8 실패는 오답이 아니라 행동 차이다 —
  mini 는 플레이북대로 즉시 승인 카드를 만들지만, gpt-4o/5 는 "라벨이 목록에 없으니
  추가할지" 되묻는다. 체커는 즉시 카드를 기대하므로 실패로 집계되나, 실사용 관점에선
  되묻기가 오히려 옳을 수 있다(체커의 한계로 기록).
- **gpt-5 의 실질 우위는 지시 준수의 견고함**: 접미 아이디(x1103) 해소, 벌크 개별 속성
  유지 등 프롬프트만으로 안 되던 것을 해낸다(BULK3). 다만 이번 라운드에 그 교정을
  **코드 가드**(join 의 접미 해소)로 옮겼으므로 모델 업그레이드 없이도 같은 결과를 얻는다.
- **사전 취합이 잘 된 경로(ACT5)는 모델을 안 탄다** — "판단은 모델, 보장은 코드" 방향의
  근거. 코드가 자료를 만들어 주면 mini/4o/5 의 답 품질이 수렴한다.

## 권고

| 용도 | 구성 |
|---|---|
| **운영 기본(권장)** | complex=gpt-4o + simple=gpt-4o-mini — 품질/속도/비용 균형 |

# 티어별 비교 (2026-08-08 추가)

위 비교는 **complex 티어만** 바꿔 본 것이다. simple 티어와 임베딩은 하는 일이 달라서
같은 잣대로 재면 안 된다 — 문장 품질 judge 로는 둘 다 보이지 않는다. 각자 **정답이 있는**
과제로 따로 쟀다(`tools/agent_tier_eval.py`).

## simple 티어 — 의도 분류 정확도 (Planner)

골든셋: 의도 21건(배터리에서 실제로 갈렸던 경계만) + 답변 깊이 4건. judge 없이 결정적 채점.

| 모델 | 의도 | 깊이 | 시간 | 토큰 | 비용 |
|---|---|---|---|---|---|
| **gpt-4o-mini** (현재) | **21/21** | 4/4 | **41s** | 119k | **$0.018** |
| gpt-5.4-nano | 21/21 | 4/4 | 52s | 121k | (단가 미확인) |
| gpt-5.4-mini | 21/21 | 4/4 | 46s | 120k | $0.195 |

**세 모델 모두 만점.** 이 과제는 이미 포화됐다 — few-shot 예시 20여 개가 실려 있어
분류 자체가 어렵지 않다. 그렇다면 **가장 싸고 빠른 것이 정답**이다: gpt-4o-mini 유지.
(비싼 모델로 바꿔도 얻을 것이 없다는 것이 이 측정의 결론이다.)

## 임베딩 — 규칙 검색 정확도

골든셋: 지식 문서 질의 10건 → 그 답이 실제로 들어 있는 문서(정답을 **집합**으로 둔다 —
한 질문의 답이 두 문서에 걸치는 경우가 있다).

| 모델 | top-1 | top-3 | 색인 시간 | 단가(/1M) |
|---|---|---|---|---|
| **text-embedding-3-small** (현재) | 9/10 | **10/10** | 3.5s | **$0.02** |
| text-embedding-3-large | 10/10 | 10/10 | 2.4s | $0.13 (6.5배) |

에이전트는 `k=3~4` 로 검색하므로 **실사용 차이가 없다**(top-3 동률). 비용이 걸리는 곳은
정적 색인(47청크)이 아니라 **동적 색인**(Jira 티켓·코멘트를 계속 임베딩)이라 6.5배가 그대로
누적된다. → 3-small 유지.

## 최종 권고 (티어별)

| 티어 | 모델 | 이유 |
|---|---|---|
| complex | **gpt-4o** | 품질/속도/비용 균형. gpt-5 계열은 대화형으로 못 쓸 만큼 느리다 |
| simple | **gpt-4o-mini** | 분류 과제가 포화 — 더 비싼 모델로 얻을 것이 없다 |
| embedding | **text-embedding-3-small** | top-3 동률인데 6.5배 싸다 |

> 주의: `gpt-5.4-mini` 는 이름과 달리 4o-mini 의 **10~15배 단가**($1.50/$9.00 vs $0.15/$0.60).
> `gpt-5.4`·`gpt-5.4-nano`·`gpt-5.5` 는 공식 단가를 확인하지 못해 `usage.PRICES` 에 없다 —
> 비용 표시가 접두 일치("gpt-5")로 떨어지므로 **실제와 다를 수 있다**(주석으로 표시해 뒀다).
