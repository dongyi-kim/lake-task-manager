# 모델 비교 — gpt-4o vs gpt-5 (2026-08-08)

에이전트의 **complex 역할**(Historian/Refiner/Assigner/Reviewer/Responder/PMO/Curator)만
대상 모델로 바꾸고, **simple 티어(Planner/Operator)와 채점 judge 는 양쪽 모두
gpt-4o-mini 로 고정**해 무거운 역할의 모델 차이만 비교했다.
측정 도구: `tools/agent_perf.py`(정량) · `tools/agent_scenarios.py`(정성, 4축 judge).
코드 기준: P-0~P-2 최적화 반영본(dca67b2).

## 정량 — 대표 4시나리오(조회/지식/생성/수정) 1회씩

| 모델 | 합계 시간 | LLM 호출 | 토큰 | 비용 |
|---|---|---|---|---|
| gpt-4o-mini (참고, 전 역할) | 155s | 33회 | 161k | $0.028 |
| **gpt-4o** | **215s** | 31회 | 150k | $0.41 |
| **gpt-5** | **1,108s** | 41회 | 300k | $1.05 |

- gpt-5 는 gpt-4o 대비 **5.2배 느리고 2배 토큰**(reasoning 토큰이 completion 으로 청구),
  2.5배 비용. 생성 플로우 한 턴이 574초 — 대화형 UX 로는 사실상 못 쓴다.
- gpt-5 는 호출 수 자체도 늘었다(31→41회): 생각이 깊어지며 도구 왕복이 많아진다
  (historian 3→7회, assigner 4→6회).
- gpt-4o 의 시간 병목은 호출당 지연(assigner 4회 37.6초)이지 토큰이 아니다.

## 정성 — 배터리 6케이스(에픽·벌크·지식·활동·수정·연관성), 동일 judge(mini)

### 해석

- **큰 모델은 신중해서 체커에 걸린다.** KNOW4·MOD8 실패는 오답이 아니라 행동 차이다 —
  mini 는 플레이북대로 즉시 승인 카드를 만들지만, gpt-4o/5 는 "라벨이 목록에 없으니
  추가할지" 되묻는다. 체커는 즉시 카드를 기대하므로 실패로 집계되나, 실사용 관점에선
  되묻기가 오히려 옳을 수 있다(체커의 한계로 기록).
- **gpt-5 의 실질 우위는 지시 준수의 견고함**: 접미 아이디(x1103) 해소, 벌크 개별 속성
  유지 등 프롬프트만으로 안 되던 것을 해낸다(BULK3). 다만 이번 라운드에 그 교정을
  **코드 가드**(join 의 접미 해소)로 옮겼으므로 모델 업그레이드 없이도 같은 결과를 얻는다.
- **사전 취합이 잘 된 경로(ACT5)는 모델을 안 탄다** — "판단은 모델, 보장은 코드" 방향의
  근거. 코드가 자료를 만들어 주면 mini/4o/5 의 답 품질이 수렴한다.
