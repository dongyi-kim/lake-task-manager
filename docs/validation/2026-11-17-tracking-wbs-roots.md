# Tracking 최상위 WBS 보정

## 원인과 변경

저장된 결과의 `module → WBS`를 화면 계층에 그대로 사용. 모듈이 단독 root일 때만 숨겨서 `WBS 미연결`이나 VOC root가 함께 있으면 ETL 계층이 다시 표시됨.

- 공통 표시 모델에서 모듈 계층 제거. 트리·요약·상위 경로 모두 `WBS → Epic → Task → Subtask`로 표시.
- 조회 조건의 모듈 선택과 원본 저장 결과는 유지. 추가 Jira/API 조회 없음.
- 기존 `unmapped`는 ID와 하위 업무를 유지한 가상 `WBS 미연결`로 표시.
- 과거 모듈 직속 업무와 최상위 독립 업무는 각각 가상 WBS에 보존. 기존 `소속 Epic 없음` 범위를 합치지 않음.
- 중복 ID가 있는 과거 결과는 원래 부모 경로로 표시 ID를 구분. 같은 이름의 WBS나 공유 티켓도 선택 범위가 섞이지 않음.
- 사용자 VOC의 가상 WBS와 분류 Epic, 현재 완료 집계, 근거·타임라인 유지.

## 실제 개발 화면

- 최상단: `실시간 수집 체계`, `배치 적재 표준화`, `WBS 미연결`, `사용자 VOC`.
- WBS 선택 경로: `전체 업무 → 실시간 수집 체계`. ETL 계층 없음.
- 모두 접으면 위 4개 WBS만 유지. DL-103 Epic의 압축 타임라인 표식 6개 유지.
- 이 동작 중 추가 Tracking 조회 0건, 브라우저 오류 0건.

## 회귀 검증

- 변경 전 새 모델 회귀 2건 실패 재현 후 수정.
- 모델·VOC·범위·보고·타임라인·정적 자산 관련 425건 통과.
- 추가 중복 `unmapped` 검사와 문구 수정 후 모델·브리핑 19건 재실행 통과.
- 계층·상세 패널 브라우저 12건 통과. 혼합 root의 WBS 깊이·접기, 기존 독립 범위, 검색·강조·원본 근거, 조회 무증가 확인.
- 변경 JS 3개 구문 검사 및 `git diff --check` 통과.

## WBS Task 명칭과 생성 구조 확정

- 사용자 재확인: 최상단 유형은 정확히 **WBS Task**. `WBS Task → Epic → Task → Subtask`로 표시 명칭 통일.
- 새 결과의 `build_result`에서도 module wrapper 생성 제거. 모듈 선택 조건과 `moduleId` 정보, WBS/티켓 ID·공유 Epic 경로·사건 집계 보존.
- 트리 가이드, 직속 하위 목록, 유형 표시, 선택 항목 헤더를 `WBS Task`로 표시. 미연결 그룹은 `WBS Task 미연결`.
- 기존 저장 결과의 module wrapper와 이전 `WBS 미연결` 이름도 같은 표시 구조로 변환. 재수집 불필요.
- backend 회귀 변경 전 실패 확인 후 `tests/tracking` 190건 통과. 관련 frontend·정적 자산 399건 통과.
- 최종 계층·상세 패널 브라우저 13건 통과. 최상단 목록·항목 유형·선택 헤더·트리 안내의 `WBS Task` 문구와 legacy 이름 변환 확인. 변경 JS 6개 구문 검사 통과.
