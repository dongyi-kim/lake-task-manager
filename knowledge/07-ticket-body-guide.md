# 본문과 댓글의 의미 작성

원 요청·현재 ticket·검증된 근거·사용자 seed가 내용의 한계다.
Puffin NDV 같은 기술 예시는 실제 적용 사실이나 현재 작업의 DoD가 아니다.

## 슬롯과 질문

ASK는 사용자만 아는 필수 값, INFER는 근거·위임 안에서 결정 가능한 값,
LATER는 후속 검증·승인에서 확정할 값이다. 모든 빈칸을 묻거나 추측하지 않는다.
알아서여도 대상·필수 범위·사람 식별·exact write payload는 해소해야 한다.
안전한 초안이 가능하면 진행하되 모르는 효과·수치·완료·원인은 구체적 확인 항목으로 남긴다.

## 본문

배경 → 작업 범위 → 완료 조건 (DoD) → 참고 순서가 기본이다.
배경은 이유, 범위는 이번 작업과 확인된 제외, DoD는 판정 가능한 조건,
참고는 이 일과 실제 관계가 있는 ticket/document link다.
Knowledge/References 등 중복 섹션을 만들지 않는다.
근거 없는 수치 목표·기술 선택·일정·새 기능을 추가하지 않는다.
부모는 전체 why·범위를, 자식은 직접 부모 안에서 자기 책임을 설명한다.
자식 제목을 부모 실행 목록으로 반복하거나 배경·참고·DoD를 모든 자식에 복제하지 않는다.

## 댓글과 seed

댓글은 현재 주제의 짧은 보고·질문·요청이다. 검토 결과를 몰라도 검토 요청은 작성할 수 있다.
검증된 담당자 mention, 실제 기준·문서 link를 연결한다.
완료 보고와 Jira In Progress가 충돌하면 각각 표시하고 확인을 요청한다.
미완성 seed는 의미·수치를 보존한다. p95가 생각보다 뒤에 높음/낮음·원인을 문법으로 채우지 않는다.
유용한 초안도 불가능하면 NEED_INFO와 구체적 질문을 반환한다.
