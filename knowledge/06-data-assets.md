# 데이터 자산·주제 조사 규칙

특정 대상 하나(테이블·적재 Job·도입한 기술·진행 중인 업무)에 대해 "지금 어떻게 되어
있느냐"를 물었을 때 지켜야 하는 규칙. 이 답의 조각은 **한 티켓에 모여 있지 않다.**

## 조각이 흩어져 있는 자리

| 조각 | 어디에 있나 |
|---|---|
| 최초 요청·배경 | VoC 티켓(Component `사용자 VoC`) 본문의 `key : value` 주입 블록 |
| 도입·구축 시점의 값 | 개발/도입 티켓 본문(Job 이름·주기·초기 스키마·초기 정책) |
| **바뀐 값** | 변경 티켓의 **changelog**(필드명이 `적재주기`·`보존기간`·`스키마`·`호환성 정책` 등) **와 코멘트** |
| 왜 바뀌었나 | 장애·이슈 티켓의 코멘트(원인·조치·후속 결정) |
| 정리된 현재 상태 | Confluence 분석·표준 문서 본문(검색 발췌 200자로는 안 보인다 — 본문을 읽어야 한다) |
| 남이 아는 사실 | **다른 대상의 티켓 코멘트**(비교·참고로 언급) |

## 판정 규칙

1. **현재 값 = 가장 최근 변경 기록.** 변경 이력이 없으면 최초 도입·구축 티켓에 적힌 값이
   현재 값이다. 변경 **전** 값을 현재 값으로 답하는 것이 가장 흔한 오답이다.
2. **이름은 원형 그대로 검색한다.** `fdc.fdc_trace_summary_ic` 를 낱말로 쪼개면 엉뚱한
   티켓이 걸린다. 스키마를 뗀 형태(`fdc_trace_summary_ic`)로도 한 번 더 본다.
3. **값마다 출처를 병기한다** — 티켓 키, 코멘트 작성자·날짜, 문서 제목.
4. **없으면 없다고 답한다.** 이름이 기록 어디에도 안 나오면 "확인된 기록 없음"이 정답이다.
   비슷한 다른 테이블·기술의 사실을 끌어다 붙이지 마라.
5. 부분만 확인됐으면 **확인된 것과 확인 안 된 것을 나눠** 말한다("적재주기는 실시간으로
   확인되지만, 스키마 정의는 기록이 없다").

## Job 명명 관례

- 배치: `etl_<테이블명>_<주기>` (예: `etl_fdc_trace_summary_ic_30m`)
- 스트리밍: `str_<테이블명>` (예: `str_eqp_sensor_raw_1s`)

주기가 바뀌면 Job 이름의 접미도 함께 바뀐다 — **옛 이름이 검색에 걸리면 그건 과거 값**이다.
