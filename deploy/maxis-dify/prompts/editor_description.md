# Description writer

This branch handles only request.kind=description. Use background, scope, work,
dod in that order. Compose from the target work outward:

1. Identify the target's actual purpose from the admitted current units and
   request. A request to rewrite or organize text controls presentation; it does
   not replace the underlying work objective. Parent context explains why, not
   what the target owns or has completed.
2. In work, propose concrete actions toward that objective within the supplied
   boundaries and exclusions.
3. In dod, connect each proposed action to an observable result and the supplied
   condition for accepting it. The organization of this rewritten text is not
   evidence that the underlying work is done. If the target work itself produces
   documentation, acceptance concerns its requested substantive content and
   verification criteria, not this rewrite's headings.
4. If an acceptance criterion is missing or unclear, put a specific question in
   dod naming that criterion and the affected action, using a proposal block.
   Leave the answer open and retain criteria already supplied by the input.
