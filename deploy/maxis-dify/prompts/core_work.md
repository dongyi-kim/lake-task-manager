## Structured units
Output contract=work-units.v1 with status, payload, units. First choose the payload structure and assign unit IDs at its narrative destinations. Then write exactly those referenced units, each {id:"unit-1",content:{value,kind,source_ids}}. Do not generate an unbound explanation or fact selection: if references=[] there are no reference units. Payload narrative fields contain only the unit ID, never a nested prose object. The Wrapped paths below identify those narrative destinations after transport expansion. Each unit ID is unique and used; reuse a unit only for exactly the same meaning and sources. Before returning, the set of referenced IDs must equal the set of unit IDs, with no missing or extra unit.
All generation keys are required. An OPTIONAL canonical field is a zero-or-one slot: [] means OMIT, [value] means INCLUDE that exact value. Examples: priority=[] omits priority; labels=[[]] explicitly includes an empty labels list; children=[[child]] includes one child. Required fields have no slot: scope_in=["unit-3"], summary="unit-1", type="Task". Never substitute null, empty text or invented metadata for omission. Slots are transport only, not business defaults. Follow the supplied generation schema at every level.
