# 초안 품질 — Claude 레퍼런스 비교 (Q6b)

에이전트(gpt-4o-mini 파이프라인)가 만든 초안을, **같은 입력·같은 조사 재료**로 Claude
(Opus)가 직접 설계한 레퍼런스 초안과 나란히 놓고 정성 평가한다. 목적은 점수가 아니라
**갭의 목록** — 갭은 프롬프트/가드 개선으로 환류하고, judge 루브릭이 그 갭을 잡을 수
있는지도 함께 점검한다(judge 도 개선 대상 — 사용자 지시).

> 배경: 배터리 체커·judge 가 green 인데 실사용 품질이 형편없던 사고(STARR NDV 건).
> 체커는 형식만 보고, judge 는 원 요청을 못 봐 주제 이탈을 못 잡았다. 이 문서의 비교가
> 그 맹점을 메우는 정성 게이트다.

## 사례 1 — STARR1: "starrocks puffin ndv 통계정보를 생성하는 파이프라인을 개발해야해"

(2턴: Epic 위임 · 범위 "최소 기능 1차 구현" · 마감 2026-09-30 · 알아서)

### Claude 레퍼런스 초안

의도 해석: StarRocks 가 읽는 ETL Iceberg 테이블에 Puffin 포맷의 NDV(고유값 수) 통계를
생성해 옵티마이저가 활용하게 하는 파이프라인. 다단계(설계→구현→연동 검증) 신규 구축 →
**Task + Sub-Task**.

- **구조**: task_with_subtasks (설계·구현·검증이 사람/기간으로 나뉜다)
- **Task**: `[ETL] StarRocks Puffin NDV 통계 생성 파이프라인 개발` — Epic: 쿼리 성능
  계열(NDV 통계는 옵티마이저 재료 — 'ETL 쿼리 성능 개선' Epic이 합치. 단, Epic 본문의
  '증분 적재'는 이 Task 의 주제가 아님을 배경에서 구분), 모듈 ETL, 마감 2026-09-30
- **본문**(4섹션):
  - 배경: 사용자 요청 사실 그대로 — StarRocks 조회 최적화를 위해 Iceberg 테이블의 Puffin
    NDV 통계가 필요. 사내 선행 이력 없음(조사 결과 명시). 2~3문장.
  - 작업 범위: 포함 — 대표 테이블 1~2개 대상 NDV 통계 생성 job + StarRocks 인지 확인.
    제외 — 전 테이블 확대, 통계 자동 갱신 스케줄 고도화, 다른 통계 유형(histogram 등)
  - DoD: ① 대표 테이블에 Puffin NDV blob 생성 확인 ② StarRocks 쿼리 플랜에서 통계 사용
    확인 ③ 실행 방법 README ④ (2~4개, 검증 가능형)
  - 참고: 조사에서 실키·실링크가 있는 것만. 없으면 "사내 선행 이력 없음"을 배경에 쓰고
    참고는 생략 — **링크 없는 문서 제목 나열은 금지**
- **Sub-Task** (기능 분화 3~4건):
  1. `Iceberg 테이블 Puffin NDV 통계 생성 job 구현` (핵심 산출물)
  2. `대상 테이블 선정·통계 수집 범위 설계` (선행)
  3. `StarRocks 통계 인지·플랜 반영 검증` (연동 확인 — 이 요청의 존재 이유)
  4. (선택) `실행·재생성 절차 문서화`
- **하지 말 것**: Epic 본문의 주제(증분 적재)로 제목·범위를 바꾸는 것, Knowledge/References
  중복 섹션, 마감을 지어내는 것

### 남은 갭 (Claude 레퍼런스 대비) — **3종 모두 2026-08-09 라운드에서 착수**

1. **도메인 추론 깊이**: 레퍼런스는 "StarRocks 가 읽는 **Iceberg 테이블**의 통계"라는
   관계를 배경·Sub-Task 에 반영한다. mini 는 사용자 낱말을 유지하지만 그 관계("Iceberg
   테이블 대상", "플랜 반영 확인")까지는 스스로 전개하지 못했다 — Sub-Task 제목이
   "설계 완료/테스트 수행"처럼 일반적이다.
   → **조치**: 원인은 배선이었다. `web_context`(외부 기술 조사)가 Historian·Curator 에만
   가고 **본문을 쓰는 Refiner 에는 안 갔다**. Refiner 재료로 이었다(`data_block` 은 비면
   빈 문자열이라 웹 조사가 돈 턴에만 붙는다 — 평소 토큰 불변). judge `topic` 축에도
   "낱말만 옮기면 4점 초과 금지"를 명시.
2. **DoD 검증성**: 레퍼런스 DoD 는 "플랜에서 통계 사용 확인"처럼 판정 방법이 담긴다.
   mini 는 "테스트 완료" 수준.
   → **조치**: `knowledge/07` 에 판정 방법 유무 **대조표**(왼쪽=없다/오른쪽=있다) 추가.
   judge 에 `scope` 축 신설로 판정 방법 없는 항목이 절반 넘으면 3점 이하.
3. **범위의 제외 항목**: mini 는 제외를 자주 생략한다(가드 없음 — 체커만 존재).
   → **조치**: `refiner.apply` 에 코드 가드 — 작업 범위 섹션이 있는데 제외가 없으면
   rationale 에 확인 필요를 남긴다. **채워 넣지는 않는다**(무엇을 빼는지는 사용자만 아는
   것이라 지어낸 제외는 날조다). judge `scope` 축 ①이 같은 것을 본다.

### judge 맹점 점검

- 개선 전 judge(4축·마지막 턴만) 는 이 사고에 **body 4점**을 줬다 — 주제 이탈·중복 섹션을
  못 잡았다. → 5축(topic, 원문 컨텍스트 포함)으로 개선.
- 그 뒤에도 갭 1·3 은 **refs/body 서술에 흡수돼 점수가 안 깎였다.** 서술이 매끄러우면
  범위·판정 결함이 그 안에 묻힌다 — 흡수되는 축에 문구만 더 넣는 것으로는 안 되고,
  **따로 떼야** 점수가 움직인다. → 2026-08-09: **6축**으로 확장하고 `scope`(범위 제외 +
  DoD 판정 방법)를 신설했다. 갭 1 은 `topic` 축을 "낱말 유지"에서 "관계 전개"까지로 넓혔다.

## 사례 2 — STR1: "미등록 테이블 30개 등록, 사람 나눠서"
