# 사용자 관점 리뷰 — 실사용 흐름별 불평 목록

> 계약을 주지 않고 화면에 보인 것만 보고 **사람처럼** 평가한 결과.
> 배터리(계약)는 내가 예상한 실패만 잡는다 — 여기는 **예상 못 한 것**을 잡는 자리다.
> 축 ③(사실)·⑤(렌더)는 코드가 실물과 맞춰 본 결과를 함께 준다.

## F1 [실무] — 새 기능을 티켓으로 (인터뷰 → 구조 → 초안)

잘된 점: 티켓 초안이 잘 구성되어 있어 진행이 용이하다.

### 축1 [annoying] 각 단계별로 작업을 명확히 구분하여 진행할 수 있도록 하기 위함입니다.
- **왜 문제인가**: 이유가 불필요하게 길어져서 핵심이 흐려졌다.
- **이렇게 나왔으면**: 간결하게 이유를 설명해 주세요.

### 축2 [blocker] 하위 작업의 완료 조건이 빠져 있다.
- **왜 문제인가**: 하위 작업이 완료되었는지 판단할 수 없어 진행이 어렵다.
- **이렇게 나왔으면**: 하위 작업별로 완료 조건을 명시해 주세요.

### 축4 [annoying] 하위 작업에 대한 설명이 없다.
- **왜 문제인가**: 하위 작업이 무엇을 의미하는지 알 수 없어 이해하기 어렵다.
- **이렇게 나왔으면**: 하위 작업에 대한 간단한 설명을 추가해 주세요.

### 축6 [nit] ‘이 구조로 진행할까요?’라는 질문이 불필요하게 길다.
- **왜 문제인가**: 간결하게 질문을 전달할 수 있다.
- **이렇게 나왔으면**: 질문을 더 간결하게 수정해 주세요.

### 축7 [annoying] ‘각 단계별로 작업을 명확히 구분하여 진행할 수 있도록 하기 위함입니다.’라는 설명이 구체적이지 않다.
- **왜 문제인가**: 어떤 방식으로 구분되는지 명확하지 않아 실질적인 도움이 되지 않는다.
- **이렇게 나왔으면**: 구체적인 작업 구분 방식을 설명해 주세요.
