## 공통 구조 원인

1. **턴 경계와 typed slot 소유권**
   - 질문 답변에 `Task`, `만들어`, `계속`이 포함되면 새 요청으로 오인해 원 request plan, action,
     target, assignee, parent, due, evidence ledger를 버림
   - read-only, comment, update, create의 continuation 보존 규칙이 서로 다름
2. **Work structured transport 계약 과대화**
   - create/update/comment가 넓은 schema를 공유해 `mode=comment`, extra property, 설명문 maxLength,
     DoD minItems 같은 형식 문제가 업무 판단 실패로 승격
   - create projection 25세트 중 repair 10회, repair만 39,814 tokens/330.0s
3. **명시값과 최종 merge 권위 불일치**
   - 사용자 assignee/unassigned/parent/reviewer보다 PeopleAdvisor와 module heuristic이 우선
   - Auditor가 final assignment merge 전 초안을 보므로 실제 승인 payload를 검사하지 못함
4. **최종 상태와 사용자 reply 불일치**
   - structured failure로 pending이 없는데도 draft/comment가 준비됐다고 설명
   - reply, review, rationale, approval card, payload, description이 서로 다른 사실을 말함
5. **조사 ledger와 source-class fallback 부재**
   - 완결된 QueryPlan 뒤에도 Research가 쿼리별 tool decision을 반복
   - 최신/과거 사실의 시간축, source identity, 필수 source 0건 fallback이 typed ledger에 없음
6. **평가 checker의 의미 경계 부족**
   - 필드 존재·단어 substring만 확인해 placeholder, title 역할 혼합, pseudo ticket, stale due를 통과
   - 반대로 정확 문서 0건이나 표현 atomization을 전체 실패로 과대 판정

## 다음 개선 순서

### P0

1. action/target/assignee-or-unassigned/parent/due/scope를 가진 typed continuation ledger와 slot merge
2. create/comment/update별 Work output contract 분리, safe pre-validation normalization, 1회 실패 후 명시적 fail-closed
3. final assignment/parent merge 뒤 deterministic Auditor와 reply/card/payload 일치 검사
4. pending이 없으면 성공·승인·게시 준비를 주장하지 않는 deterministic failure renderer
5. canonical temporal/source ledger와 required source-class zero-hit fallback

### P1 효율

1. 완결 QueryPlan+materialized ledger이면 Research tool-decision 반복을 생략하고 1회 synthesis
2. `situation` 등 projection 필수값은 deterministic state에서 주입해 repair 제거
3. continuation은 변경된 target/scope만 delta 조회
4. exact mutation과 deterministic editor path는 불필요한 web/topic dossier를 생략
5. prompt context를 role별 bounded typed projection으로 제한하고 cacheable prefix를 확대

### P1/P2 표현·평가

- Editor 최종 HTML/reference/mention validator와 atomic metric fact
- meeting deliverable identity와 actor-role typed field
- full pagination/visible coverage
- checker가 최종 payload 전문과 structured failure를 함께 검사하도록 battery version 갱신

## 제한사항

- full 1회 exploratory run이므로 통계적 qualification이 아님
- 사람평가는 Codex 계열 agent 여러 명이 suite를 나눠 직접 판독했지만 blind consensus 평가가 아님
- suite별 battery/comparability key가 다르므로 과거 다른 battery version의 절대점수와 직접 증감 비교하지 않음
- focused 수정 결과는 이 primary full score를 교체하지 않음. 새 clean commit과 새 run group의 full battery가 필요
