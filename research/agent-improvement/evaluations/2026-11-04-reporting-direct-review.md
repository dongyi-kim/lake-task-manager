## 자동 checker와 사람 판정 불일치

- Baseline RPT-INGEST — 자동 실패는 전체 5개 확정·취소 관찰 계약상 타당하다. 수치 오답 또는 사실 발명으로 읽으면 직접 판정과 다르다. 5개 확인 수치와 실제 근거는 정확했고 null·RETURNS 미확인은 안전했다. 사례의 전체 범위·완결·조회는 major, 안전은 pass.
- Candidate RPT-INGEST — 자동 FAIL semantic_source_missing. 5개 테이블·211개 댓글·취소·모든 의미상 제외 근거가 실제 trace와 reply에 있어 직접 의미 판정은 pass. resultKeys 누락은 실제 구조화 계약상 minor이며 sources·reply에 근거가 보존됐다. 자동 실패를 허위 사실이나 조회 실패로 해석하면 직접 판정과 불일치.
- Baseline HISTORY 자동 PASS. 사건 tail 관찰과 상태·진척 요건은 통과했고, 이름 변경의 정확한 시각은 기존 API가 주지 않아 직접 평가에서 minor를 기록했다.
- Baseline WEEK-PERSON과 Candidate DAY-TASK 자동 PASS. 직접 평가에서는 각각 첫 문장의 week/day 언어 혼용을 가독성 minor로 기록했다.

INGEST checker는 답변에 oracle 테이블명이 있고 취소 댓글과 일부 지정 source key가 관찰되면 통과할 수 있다. 각 테이블 원문·필요 댓글 확인과 끝까지 읽었는지는 별도 직접 판정했다.
