# app/agent/retrieval — RAG 2계층

## 왜 두 계층인가

| | 정적 (`static_index`) | 동적 (`dynamic_index` + `harvest`) |
|---|---|---|
| 무엇 | `knowledge/` 규칙 문서 | Jira 티켓·코멘트·Confluence 문서 |
| 얼마나 자주 바뀌나 | 거의 안 바뀜 | 계속 바뀜 |
| 갱신 | 파일 내용 해시가 바뀌면 통째로 다시 | **바뀐 문서만** 증분 |
| 신선도 책임 | 없음(규칙은 오래돼도 맞다) | **벡터가 아니라 실시간 검색이 진다** |

## 동적 색인의 핵심 — 신선도와 비용을 동시에

벡터 색인만으로 Jira 를 검색하면 **어제 만든 티켓을 못 찾는다**. 그렇다고 매번 전부 임베딩하면
비싸고 느리다. 그래서 순서를 나눈다.

```
① 1차 검색은 항상 실시간   search_all (JQL/CQL) — 방금 만든 티켓도 잡힌다. 신선도는 여기서 100%
② 장부와 대조             manifest — 안 바뀐 건 건너뛴다 (대개 대부분)
③ 새것/바뀐 것만 임베딩    upsert
④ 그제서야 의미 검색       ①이 못 하는 걸 한다 — 키워드가 안 겹치는 같은 이야기
                          "CDC" ↔ "변경분 실시간 반영"
```

벡터는 키워드 검색을 **대체하지 않고 보강**한다. 이 구조라서 **TTL 이 벡터에 걸리지 않는다** —
원본이 안 바뀌었으면 6개월 된 벡터도 여전히 정확하다. 낡을 수 있는 건 결과 목록뿐이다.

## 재임베딩 판정 2단 (`manifest.py`)

1. **`updated`** — Jira/Confluence 가 주는 수정 시각. 대부분 이걸로 끝난다. 싸다.
2. **`content_hash`** — updated 는 그대로인데 내용이 바뀌는 경우가 있다. 1차를 통과해도 해시가
   다르면 다시 넣는다.

여기에 **`embed_sig`(provider|model)** 가 더 붙는다. 이게 가장 중요하다 — provider 를
fake→openai 로 바꾸면 벡터 공간이 통째로 다르다. **차원이 우연히 같으면 에러도 안 나고 그냥
엉뚱한 걸 찾아온다.** 조용히 틀리는 쪽이 훨씬 나쁘므로 서명이 다르면 전부 버린다.

**벡터와 장부는 반드시 함께 버린다**(`reset()`). 따로 버리면 "장부엔 있는데 벡터가 없는" 상태가
되어, 이미 넣었다고 건너뛰면서 아무것도 못 찾는 조용한 고장이 된다.

## upsert 가 delete-then-add 인 이유

FAISS 는 제자리 갱신이 없다. 옛 조각을 안 지우고 새 조각만 넣으면 **같은 티켓의 옛 버전이 계속
검색된다** — "이미 취소된 방침"을 근거로 답하는 일이 생긴다. 장부의 `chunk_ids` 로 먼저 지운다.

## 무엇을 한 문서로 보나 (`harvest.py`)

**티켓 + 그 코멘트 = 한 문서.** 코멘트를 따로 색인하면 "DL-118 코멘트 3번"만 걸려서 무슨 티켓
이야기인지 모른 채 근거로 쓰인다. 합쳐 두면 어느 조각이 걸리든 머리에 티켓 키와 제목이 붙어 있다.

**링크 2홉** — 검색 키워드는 그 단어를 쓴 문서만 찾는데, 실제 맥락은 링크 건너편에 있는 경우가
많다(티켓엔 "설계는 문서 참고"라고만 적혀 있고 결정은 Confluence 에). 그래서 1홉 결과 상위 몇
건에서 연관 티켓·관련 문서로 한 번 더 뻗는다. 3홉부터는 프로젝트 절반이 딸려 오므로 안 간다.

## 조각내기 (`chunk.py`)

**제목 경계로 자른다.** 고정 길이로 자르면 표 한가운데, 문장 한가운데가 끊긴다. 절이 너무 길
때만 길이로 한 번 더 쪼갠다 — 순서가 반대면 경계가 이미 깨져 있다.

각 조각 머리에 **제목 경로**를 박는다(`01-ticket-rules.md > Story Point`). 조각만 떼어 놓으면
무엇에 대한 규칙인지가 사라진다. 머리를 달면 임베딩에도 그 맥락이 실리고 출처도 남는다.

## 저장 위치

```
.cache/agent_index/
  static/    meta.json + FAISS      규칙 색인
  dynamic/   meta.json + FAISS      티켓·문서 색인
  manifest.sqlite3                  무엇을 언제 어떤 내용으로 넣었나
```

`.cache/` 는 통째로 gitignore 대상이며, 지워도 다음 질의에서 다시 만들어진다.

## 미리 굽기

```bash
python -m app.agent.retrieval.static_index      # 첫 질의를 빠르게
```

동적 색인은 미리 구울 수 없다(무엇을 물을지 모른다) — `deep_search` 가 부르는 시점에 쌓인다.
