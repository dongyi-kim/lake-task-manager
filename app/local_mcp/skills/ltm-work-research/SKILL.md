# 업무 맥락과 진척 조사

사용자가 묻는 범위에 필요한 근거를 찾아 사실·판단·미확인을 구분한다. 조회 성공은 조사 완료와 다르다. 이 스킬은 평가 후보이며 실제 품질·성능이 검증됐다는 의미가 아니다.

## 시작과 필요한 참고 자료

참고 자료를 전부 읽지 말고 이번 질문에 필요한 것만 선택한다. 이미 읽은 같은 URI/digest는 재사용한다.

1. 여러 대상은 [묶음 조회·재사용](references/read-strategy.md)으로 수집 계획을 세운다. 후보 탐색은 `search_issues`, 정해진 key 집합은 `get_tickets`로 묶어 읽는다. 본문은 기본 제외하고 필요한 집합만 `include_description=true`로 요청한다. 받은 필드를 key별로 다시 읽지 않는다.
2. 대상·인물·기간이 모호하면 [범위·인물·시점](references/research-scope.md)을 참고한다. 복구 요청이면 먼저 기존 `resume.md`를 읽는다.
3. 여러 페이지·긴 기록 등 중단 비용이 큰 조사에는 수집 전에 [중간 저장과 재개](references/checkpoint-resume.md)를 읽고 조사 폴더를 준비한다. [저장 예제](references/checkpoint-example.json)는 합성 자료다. 짧은 단건 확인에는 생략할 수 있다.
4. 전체 댓글·긴 레코드를 읽을 때는 [근거 수집과 이어 읽기](references/research-evidence.md)를 읽고 실제 페이지/레코드 위치를 따른다. 이력은 정확한 변경 시점·전후값·과거 담당·충돌 해소에 필요할 때만 추가한다.
5. 수치·기여·계층 단위를 해석하면 [집계](references/work-counting.md), 종료 범위가 불명확하면 [요청 대응표](references/request-matrix.md), 문장·양식 보완이 필요하면 [한국어 작성](references/korean-writing.md)을 참고한다.

## 조사와 종료

- 관련 업무를 찾고 사람·테이블의 식별 근거를 확인한다. 제목 일치만으로 같은 업무나 같은 테이블로 합치지 않는다.
- 부모가 오래 갱신되지 않았더라도 질문에 필요한 하위 관계를 확인한다. 관련 자식 본문·댓글을 읽되 전체 자식 이력을 일괄 조회하지 않는다.
- 결정·실행·변경·취소 사건을 시각과 출처에 연결한다. 현재 담당, 보고, 댓글 작성, 실제 수행을 구분한다.
- 저장 가능한 환경에서는 정상 응답을 먼저 기록하고 진행 상태를 갱신한다. 이미 확보한 근거를 분석만 못 했다면 재조회보다 분석부터 이어간다.
- 근거가 충분하면 일반 요약을 마칠 수 있다. 전체 검토·정확 집계 요청은 필요한 페이지·긴 레코드를 끝까지 읽거나 미확인 범위를 남긴다.
- 동명이인·동명 테이블이 결과를 바꾸고 해소되지 않으면 구체적인 후보를 제시해 한 번 확인한다. 인증·권한·통신 실패는 0건이 아니다.

## 결과

질문에 대한 답을 먼저 쓰고, 필요한 경우 사건 흐름·진척·기여를 표로 정리한다. 핵심 주장에는 실제 읽은 티켓·댓글·문서 revision의 근거를 붙인다. 확인한 범위와 기준 시각, 상충 자료, 미확인·제외 이유를 구분한다. 저장했다면 실제 폴더와 다음 재개 작업을 알린다.

보고서가 필요해지면 기존 조사 근거를 재사용해 `ltm-work-reporting`을 선택한다. 티켓·댓글·문서로 게시하는 요청은 해당 작성 스킬과 [초안 검토](references/draft-review.md)를 따른다. 조사 요청 자체는 게시 승인이 아니다.
