# 조회 기준과 재사용

조회 전에 필요한 대상·필드·추가 근거를 정한다. 단건을 여러 번 읽기보다 여러 대상을 묶어 적은 횟수로 수집한다. 이미 얻은 동일 근거는 로컬 조사 자료와 공유 캐시를 활용한다. 저장했다는 이유만으로 최신 자료가 되는 것은 아니다.

## 묶음 조회와 필요한 본문만 읽기

- 대상 key가 이미 정해졌으면 `get_tickets(keys=[...])`로 100건 이하씩 묶어 읽는다. 본문이 필요한 key 집합만 `include_description=true`로 요청한다. 후보 탐색은 `search_issues`, 단건 상세·렌더링·편집 원문은 `get_ticket`을 쓴다. 기본정보를 먼저 하나씩 읽고 같은 본문을 다시 조회하지 않는다. 본문은 Jira 원문 형식이며 렌더링·편집용 HTML과 구분한다.
- 목록·현재 상태·담당·관계만 필요하면 기본값 `include_description=false`를 유지한다. 후보가 불명확할 때는 `detail="summary"`로 범위를 먼저 좁히고, 본문이 필요한 후보 집합에만 포함을 켠다. 다른 필드를 켜고 끄는 옵션을 만들지 않는다.
- 다건 결과의 `missingKeys`/`complete`를 확인한다. 미반환 key는 권한·비가시성 등으로 확인하지 못한 것이며 존재하지 않는다고 단정하지 않는다. `descriptionMissingKeys`에 있거나 실제 필드가 없으면 본문을 읽었다고 하지 않는다. 반환된 null/빈 본문과 구분한다.
- 검색에서도 본문 포함 옵션을 쓸 수 있다. `include_description`은 metadata의 detail과 독립적이다. 다음 페이지에는 같은 JQL·snapshotId·본문 포함 값을 유지한다. 값을 바꾸면 새 첫 페이지 검색이다.
- 검색·`get_descendants`가 이미 반환한 상태·담당·부모 관계·본문은 재사용한다. 같은 값을 확인하려고 key마다 `get_ticket`을 반복하지 않는다. 빠진 필드, 꼭 필요한 최신 확인, 렌더링·편집 원문만 해당 key로 보완한다.
- 허용 범위 안에서 필요한 데이터가 한 페이지에 들어오도록 크기를 정하되 응답량과 서버 상한을 고려한다. 불필요하게 한 건씩 페이지를 나누지 않고 실제 nextStartAt과 snapshot을 따른다. 사용자가 정한 페이지 크기는 지킨다.
- 댓글·이력·연관 문서는 실제 판단에 필요한 key만 추가로 읽는다. 전체 검토가 필요하다는 것을 이미 알면 preview를 거듭 읽지 말고 해당 원본을 끝까지 페이지 조회한다. 제공되지 않는 다건 댓글/이력 인자는 가정하지 않는다.

MCP 단건 호출을 동시에 여러 개 보내도 Jira의 개별 요청 수가 줄어드는 것은 아니다. 실제 Jira 검색 한 번으로 여러 본문을 받는 경로와 구분한다. 부하는 MCP 호출 수뿐 아니라 upstream 요청 수·응답량·시간으로 확인한다. 근거 완전성을 희생해 호출 수를 줄이지 않는다.

## 시점과 재사용

- 현재 상태·오늘의 현황·게시 직전 확인은 최신 확인이 필요하다. `get_ticket(fresh=true)`처럼 실제 도구 schema가 제공하는 인자만 사용한다.
- 과거 보고도 최근 취소·수정이 실적 판단을 바꾸면 해당 근거를 갱신한다. 변경 불가능한 특정 문서 revision은 재사용할 수 있지만 최신 revision 확인과 구분한다.
- 검색 membership, 티켓 필드, 댓글, 문서 본문, 사진·Epic 이름의 나이는 다를 수 있다. 새 필드 하나를 읽었다고 전체 검색·조사의 기준 시각을 새것으로 표시하지 않는다.
- cache metadata가 없으면 수집 시각을 모른다고 표시한다. 로컬 저장 시각은 upstream 수집·검증 시각을 대신하지 않는다.
- snapshot의 다음 페이지는 같은 snapshot을 이어 읽는 것이다. 최신 검색이 필요하면 첫 페이지부터 다시 시작한다.
- cache 수준·JQL 전략은 현재 연결의 실제 schema에서 발견한 경우에만 사용한다. 이 가이드는 아직 구현되지 않은 cache_mode나 strategy 인자를 제공한다고 가정하지 않는다.

결과에 조사 기준 시각과 자료 수집 시각, 재사용·갱신 범위, 갱신하지 못한 이유를 필요한 만큼 명시한다. 실패 때 허용 나이를 조용히 늘리거나 오래된 자료를 최신 확인 완료로 표현하지 않는다.
