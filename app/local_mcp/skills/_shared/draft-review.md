# 제출 전 초안 검토 권장

댓글·티켓 본문·Confluence 문서를 작성하거나 수정할 때는 **제출 전에 사용자에게 초안을 공유하고 확인받는 것을 권장**한다. 전이 댓글과 일괄 생성의 본문도 포함한다. 이는 Agent의 작성 가이드이며 MCP 서버의 필수 승인 절차나 추가 승인 팝업이 아니다.

## 권장 진행 순서

1. 필요한 자료와 최신 편집 원문을 조회하고, 대상·필수 필드·내용을 먼저 정리한다. 검토할 결과를 만들기 전에 막연히 작업 허락부터 묻지 않는다.
2. 사용자가 읽을 수 있는 문장·목록·표로 초안을 보여준다. HTML/XHTML/JSON payload만 제시하지 않는다. 제목, 게시할 티켓 key 또는 문서 Space·부모/문서 ID, 새 작성인지 수정인지도 표시한다. 멘션 대상, 첨부 파일·이미지, 추가할 이슈·문서 연결도 알 수 있게 적는다.
3. 수정이라면 바뀌는 부분과 삭제할 내용을 명확히 보여주고 나머지는 보존한다고 설명한다. 일괄 생성은 항목별 제목·대상·필드·본문을 검토할 수 있게 제시하고 묶음 단위로 확인받는다. 개수만 보여주거나 같은 묶음의 각 행마다 확인을 반복하지 않는다.
4. 별도의 제출 지시가 없다면 이 초안을 해당 대상에 게시할지 확인을 요청한다. 확인을 요청한 뒤에는 답변 전까지 관련 쓰기를 실행하지 않는다. 무응답·시간 경과를 승인으로 해석하지 않는다.
5. 확인된 내용으로 제출하고 실제 저장 결과를 재조회한다. 승인 뒤 내용·대상·삭제 범위가 실질적으로 바뀌면 변경된 초안을 다시 공유하고 확인받는 것을 권장한다. 같은 내용의 형식 변환이나 안전한 동일 요청 재시도는 재확인 대상이 아니다.

초안 검토만을 위해 Jira/Confluence에 문서·댓글을 게시하거나 파일을 업로드하지 않는다. 첨부 예정 파일명과 이미지 설명으로 먼저 보여주고, 제출 단계에서 필요한 생성·업로드·본문 반영을 수행한다. 서버가 발급한 key·첨부 경로로 승인된 참조를 채우는 것은 내용 변경이 아니다.

## 이미 주어진 지시와 승인

- 사용자가 **해당 초안·대상에 이미 승인**했거나, 정확한 내용을 주며 “이대로 등록해”, “확인 없이 바로 제출해”라고 했다면 같은 확인을 반복하지 않는다. 세션에서 이미 허용한 자동 제출 범위도 존중한다.
- 단순히 “작성해 줘”라고 했고 Agent가 내용을 구성하는 상황에는 위 검토 흐름을 권장한다. “초안만 보여줘”는 게시 권한이 아니다.
- 확인은 제시한 내용·대상에 대한 것이다. 다른 티켓·문서나 무관한 필드 수정까지 확대하지 않는다. 승인된 작업에 실제 필수 정보가 빠져 있으면 그 정보만 확인한다.
- Confluence 버전 충돌로 최신 원문과 다시 합쳤다면 실질적으로 달라진 부분을 보여준다. 승인된 예전 원문으로 다른 사람의 변경을 덮어쓰지 않는다.

예: “DL-123 댓글 초안: … / 멘션: 확인된 담당자 / 첨부: result.png. 이 내용으로 게시할까요?”처럼 검토 가능한 내용을 먼저 제시한다. 사용자가 “이대로 게시”라고 답하면 다시 묻지 않고 제출·결과 확인으로 이어간다.
