# 근거에 따른 업무 집계와 보고

확인된 실적을 요청한 기간·단위·양식으로 정리한다. 수집한 티켓 수와 업무 산출물 수는 다른 지표다. 이 스킬은 평가 후보이며 실제 모델 검증은 별도다.

## 필요한 참고 자료와 순서

1. [범위·인물·시점](references/research-scope.md)으로 기간과 집계 대상을 고정한다. 사용자 양식과 이전 보고를 먼저 읽고 문서 ID·revision·기준 시각을 기록한다.
2. 여러 자료·페이지를 읽거나 정확 집계를 하면 [중간 저장과 재개](references/checkpoint-resume.md)에 따라 조사 폴더를 만든다. 재개 요청이면 `resume.md`와 manifest부터 확인한다. [저장 예제](references/checkpoint-example.json)는 실제 실적이 아니다.
3. [근거 수집](references/research-evidence.md)으로 본문·댓글과 참조 문서를 확인한다. 일반 보고라는 이유만으로 모든 이력을 읽지 않는다. 필요한 취소·제외 근거가 뒤쪽에 있으면 댓글 전체를 읽는다.
4. [계층과 집계](references/work-counting.md)에 따라 산출물·사건별 ledger를 작성한다. 현재 상태와 기간 내 실제 실행을 구분한다.
5. [조회 기준](references/read-strategy.md)으로 재사용할 자료와 갱신할 자료를 결정한다. [요청 대응표](references/request-matrix.md)와 [한국어 작성](references/korean-writing.md)으로 결과를 검수한다.

## 보고 계약

- 사용자 양식의 제목·열·순서를 유지한다. 없는 값은 미확인, 조회 실패, 해당 없음, 확인 결과 없음 중 실제 관측에 맞게 적는다.
- 기간 실적은 완료일·실행 댓글 등 근거에 따른다. `updated`나 현재 Done만으로 과거 완료·소유자를 결정하지 않는다.
- 운영실적은 신규 적재 / 적재 변경·개선 / 적재 중단·삭제별로 완료 티켓·VoC·고유 테이블·작업 처리 횟수를 구분한다. 전체 고유 테이블은 분류별 합이 아니라 union이다.
- 이전 보고와 비교하면 신규 진척, 변경·취소, 계속 미완료, 이번 범위에서 제외된 항목을 구분한다. 과거 revision이 없으면 당시 보고를 재현했다고 말하지 않는다.
- 공동 작업은 개인별 근거를 보존하고 전체 합계에서 동일 산출물·사건을 중복 계산하지 않는다. 확인하지 못한 기여는 추정하지 않는다.
- 계산에 쓰인 대상·사건·제외 이유와 근거를 저장한다. 중단 후에는 저장한 결과를 읽고 빠진 수집·판단부터 이어간다.

## 제출 전 확인

범위·시간대·집계 단위, 분류별 수치와 전체 합계, 취소·중복·기간 밖 제외, 실제 근거 링크, 미확인 범위, 한국어의 수치·부정·보류 의미를 확인한다. 필요한 근거가 없으면 확인된 소계와 남은 범위를 제시한다.

결과는 읽을 수 있는 초안이다. 실제 티켓·댓글·Confluence 게시·수정 요청이 있을 때 기존 작성 스킬과 [초안 검토](references/draft-review.md)를 사용한다. 이미 승인된 내용이나 직접 게시 지시를 다시 확인하지 않는다.
