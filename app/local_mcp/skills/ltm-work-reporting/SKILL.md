# 근거에 따른 업무 집계와 보고

확인된 실적을 요청한 기간·단위·양식으로 정리한다. 수집한 티켓 수와 업무 산출물 수는 다른 지표다. 이 스킬은 평가 후보이며 실제 모델 검증은 별도다.

## 필요한 참고 자료와 순서

참고 자료를 전부 읽지 말고 이번 보고에 필요한 것만 선택한다. 이미 읽은 같은 URI/digest는 재사용한다.

1. 여러 대상은 [묶음 조회·재사용](references/read-strategy.md)으로 수집 계획을 세운다. 후보 탐색은 `search_issues`, 정해진 key 집합은 `get_tickets`로 묶어 읽는다. 본문은 기본 제외하고 필요한 집합만 `include_description=true`로 요청한다. 받은 필드를 key별로 다시 읽지 않는다.
2. 기간·인물·범위가 모호하면 [범위·인물·시점](references/research-scope.md)을 참고한다. 사용자 양식·이전 보고가 있으면 읽고 문서 ID·revision·기준 시각을 기록한다.
3. 여러 페이지·긴 기록 등 중단 비용이 큰 집계는 수집 전에 [중간 저장과 재개](references/checkpoint-resume.md)를 읽고 준비한다. 재개는 `resume.md`·manifest부터 확인한다. [저장 예제](references/checkpoint-example.json)는 합성 자료다.
4. 전체 댓글·긴 레코드를 읽을 때는 [근거 수집과 이어 읽기](references/research-evidence.md)를 읽는다. 완전 집계에 필요하면 preview를 반복하지 말고 원본을 끝까지 읽는다. 일반 보고라는 이유로 모든 이력을 추가하지 않는다.
5. [계층과 집계](references/work-counting.md)로 산출물·사건별 ledger를 작성한다. 종료 범위가 불명확하면 [요청 대응표](references/request-matrix.md), 문장·양식 보완이 필요하면 [한국어 작성](references/korean-writing.md)을 참고한다.

## 보고 계약

- 사용자 양식의 제목·열·순서를 유지한다. 없는 값은 미확인, 조회 실패, 해당 없음, 확인 결과 없음 중 실제 관측에 맞게 적는다.
- 기간 실적은 완료일·실행 댓글 등 근거에 따른다. `updated`나 현재 Done만으로 과거 완료·소유자를 결정하지 않는다.
- 운영실적은 신규 적재 / 적재 변경·개선 / 적재 중단·삭제별로 완료 티켓·VoC·고유 테이블·작업 처리 횟수를 구분한다. 전체 고유 테이블은 분류별 합이 아니라 union이다.
- 이전 보고와 비교하면 신규 진척, 변경·취소, 계속 미완료, 이번 범위에서 제외된 항목을 구분한다. 과거 revision이 없으면 당시 보고를 재현했다고 말하지 않는다.
- 공동 작업은 개인별 근거를 보존하고 전체 합계에서 동일 산출물·사건을 중복 계산하지 않는다. 확인하지 못한 기여는 추정하지 않는다.
- 계산에 쓰인 대상·사건·제외 이유와 근거를 저장한다. 중단 후에는 저장한 결과를 읽고 빠진 수집·판단부터 이어간다.

## 제출 전 확인

범위·시간대·집계 단위, 분류별 수치와 전체 합계, 취소·중복·기간 밖 제외, 실제 근거 링크, 미확인 범위, 한국어의 수치·부정·보류 의미를 확인한다. 필요한 근거가 없으면 확인된 소계와 남은 범위를 제시한다.

결과는 읽을 수 있는 초안이다. 실제 티켓·댓글·Confluence 게시·수정 요청이 있을 때 기존 작성 스킬과 [초안 검토](references/draft-review.md)를 사용한다. 이미 승인된 내용이나 직접 게시 지시를 다시 확인하지 않는다.
